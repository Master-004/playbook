# ADR-0003: Track work in GitHub Projects

- **Status:** Accepted
- **Date:** 2026-10-09
- **Author:** Founder

## Context
We need one place to prioritize and track work that new engineers can learn in minutes.

## Decision
Use GitHub Projects with GitHub Issues: https://github.com/users/Master-004/projects/2/views/1

## Options considered
| Option | Pros | Cons |
| --- | --- | --- |
| **GitHub Projects** | Lives next to the code; issues and PRs link automatically; no extra tool | Fewer features than Jira |
| Trello | Very simple | Not linked to code; thin as we grow |
| Linear | Fast, built for software teams | Another tool and bill |
| Jira | Powerful | Heavy setup for a startup |
| ServiceNow | Enterprise IT workflows | Far too heavy for a startup |

## Consequences
Everyone needs GitHub access (they already do for code). Revisit if we add non-engineering teams to the board.
